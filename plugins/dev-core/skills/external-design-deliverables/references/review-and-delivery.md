# Review and delivery

Produce the package required by the actual agreement. Reuse existing document
formats and source artifacts. Keep client-readable meaning and implementation
precision aligned through a shared version and stable screen/job IDs.

Check the applicable items before requesting sign-off:

- Trace screens and jobs to scope, roles, and business flows.
- Include relevant failure, no-permission, and recovery states.
- Match permission references to the authoritative policy.
- State each job's run identity, idempotency, recovery, and error-record handling.
- Resolve broken cross-references and verify rendered diagrams or visual artifacts.
- Identify remaining assumptions and required owner decisions explicitly.

Separate **draft**, **ready for review**, and **agreed for delivery**. Record the
reviewed version, agreement date, and approver only when supported by evidence.
Track later changes against that baseline. Reuse a sign-off already granted for
the same scope instead of requesting it again.

The owner retains contractual scope and acceptance decisions; the agent may
prepare and revise a complete reviewable package using authorized decisions.
Sending that package, scheduling a meeting, or publishing it externally requires
the appropriate existing authorization. A local artifact is not evidence that a
client received or accepted it.

When the task includes acceptance clauses or liability, use the governing contract
and current primary sources, and leave final legal judgment to qualified counsel.
Do not add a contract workflow to an ordinary internal design task.
